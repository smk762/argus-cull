# Argus Cull

A demo for [argus-curator](https://github.com/smk762/argus-curator). Point it at a folder and see which images the curator would keep, and why. The grid, the path list, and export all use the filter the curator already applies. The browser does not score images.

Lightbox is the demo for argus-lens. This is the demo for the curator. The suite UI stays in argus-studio.

## Run

Curator 0.6 publishes `POST /scan/{id}/select`, `GET /image`, NudeNet, SingGuard with named policies and variants, image batches on the scan stream, `GET /scans`, `POST /scan/{id}/delete`, `POST /scan/{id}/cancel`, and `POST /scans/purge`; 0.7 adds the set age (`set_age` on `/health`); 0.8 adds `GET /guard/policies` (`guard_policy_text` on `/health`) so the page can show the wording a verdict was judged against; 0.8.1 names SingGuard's own "Adult Content (Non-criminal)" under Safe, because a "not this rule" line under a risk heading was read as a match. Curator 0.10 adds the CUDA image, person boxes and `people_check`, and falls back to `fast` on a SingGuard server without `cascade`. The compose file runs the published `ghcr.io/smk762/argus-curator:latest-gpu` image, given the GPU (`gpus: all`; the host needs the NVIDIA container runtime and a CUDA 13 driver, or use `:latest` and drop `gpus`), with a NudeNet 640m server beside it and an optional EraX-NSFW sidecar for frames NudeNet does not score. SingGuard is agent-composer on the LAN, the same guard darkroom uses:

```bash
cp .env.example .env
docker compose up --build
```

The UI is http://localhost:3000 and the curator is http://localhost:8101. Both ports are published on this host, so another device opens `http://<this-host>:3000` and does not need a clone. With the default `NEXT_PUBLIC_CURATOR_URL` the browser calls the curator on that same host, port 8101; a value naming another machine is used as written. Name that page origin in `CURATOR_CORS_ORIGINS` (a set value replaces the localhost allow-list, so keep `http://localhost:3000` and `http://127.0.0.1:3000` in the list). `NEXT_PUBLIC_CURATOR_URL` is baked into the web image. The default source mount is `./fixture`. Export lands in `./out`. NudeNet 640m is on unless `ARGUS_CURATOR_NUDENET_URL` is set empty. EraX is on unless `ARGUS_CURATOR_ERAX_URL` is set empty: when NudeNet returns no exposed score, curator maps EraX's hits onto the same labels. The curator container waits for either of the two to answer `/health` (the `nsfw-ready` service) before starting, so a scan started right after `docker compose up` does not record failed checks while they load; if neither is up after about five minutes, Compose warns and starts it anyway. SingGuard is agent-composer's `/api/guard/check` (`ARGUS_CURATOR_SINGGUARD_URL`, default `http://192.168.1.198:9150`), the same guard darkroom uses: one model, one policy, the same verdicts. This compose file does not run a second Sing-Guard-4b. Set the URL empty to turn the check off. Cull scans queue on that box with darkroom's pre-flights. Composer loads images through Ollama, which is pickier than the curator's decoder, and re-encodes the frame before the model sees it. `ARGUS_CURATOR_SINGGUARD_THINKING=fast-slow` also records why a rule fired. In that mode the model writes a fast first-line signal, reasons, then gives its final judgment in an `<answer>` tag; the two can disagree, and the server records the answer. A verdict from an earlier server that kept the first line shows as unsafe with the rule `Safe`; the detail view names the conflict, and a rescan settles it. The reasoning also tends to defer to that first line ("follow the hint") even when its own steps found no rule matched, so `slow` is the fast-slow prompt with the assistant turn begun at `[Step 1]`, so the first verdict the model writes is the reasoned one. On the two posed-nude test frames, slow passed every run with or without context while fast-slow flagged one; it is also no slower. A fourth mode, `cascade`, runs `fast` on every frame (about a second) and `slow` only on the frames fast flags, and slow's verdict stands; the response carries `fast_verdict` and `fast_rule` so a reader sees what the screen said, and `thinking` names the mode that judged. A cascade pass that never needed slow comes back as `thinking: fast`, which is the short-circuit. Fast's verdict is the same first token fast-slow writes before reasoning, so it over-flags rather than under-flags: on fourteen frames from three sets it flagged twelve, slow cleared ten of those and kept two for a reason, and nothing fast passed was flagged by slow. It is a one-way screen: a frame fast passes is not looked at again. `ARGUS_CURATOR_SINGGUARD_THINKING` picks the mode the curator asks for, `cascade` by default (curator 0.6; 0.5 could only ask for `fast` or `fast-slow`). `ARGUS_CURATOR_SINGGUARD_CONTEXT` (default `age,folder,caption`) sends what the scan already knows about a frame, the MiVOLO age estimate, the folder name, and any lens caption, as recorded context, which is what a frame with no detected face needs. To run the old in-process `singguard` service on this GPU instead: `docker compose --profile local-singguard up` and `ARGUS_CURATOR_SINGGUARD_URL=http://singguard:9150`. That copy cannot do text-only checks. Do not run it beside composer. `SINGGUARD_FORCE_THINKING` on that profile judges every request in one mode whatever was asked, for experiments. `SINGGUARD_MAX_NEW_TOKENS` (2048) is its generation budget for the reasoning modes; a check cut off before its `<answer>` fails with HTTP 500 and the service logs the tail of the text, so raise it if that log appears.

To build the sibling `../argus-curator` checkout instead of the published image:

```bash
docker compose -f docker-compose.yaml -f docker-compose.local-curator.yaml up --build
```

`NEXT_PUBLIC_CURATOR_URL` is baked in at image build time and defaults to `http://localhost:8101`, which is the published port the browser can reach.

The curator runs the CUDA image (`latest-gpu`, `gpus: all`), so the host needs the NVIDIA container runtime and a CUDA 13 driver. On a host without one, use `ghcr.io/smk762/argus-curator:latest` and drop `gpus`. After a curator release, `docker compose pull argus-curator` picks up the new image; Compose does not do that on `up` alone. The curator takes turns on the GPU with argus-lens through a lock file in `ARGUS_GPU_LOCK_DIR` (`/tmp/argus-gpu` on the host); lens must mount the same directory. Set `ARGUS_GPU_COORDINATOR=none` to turn that off.

Put machine-local changes like those in `compose.override.yaml`, which compose merges automatically and git ignores. Check it after an update: an override that pins its own `image:` keeps the old curator, or names one that cannot be pulled.

Move stays off unless `CURATOR_ALLOW_MOVE=1` is set on the curator service. The export dialog names move as destructive and disables it when the server refuses it.

Without Docker, from `web/`:

```bash
npm install
npm run dev
```

and, from the curator repo, `argus-curator serve --cors --port 8101 --source-root … --export-root …`.

## What the page does

Scan streams progress from `POST /scan/folder/stream`. Image batches arrive while the scan is still running, so the grid fills before the slow checks finish, and the bar keeps the phase and the count, one row per phase when face detection and NudeNet run together (curator 0.5.1). A tile still waiting on those checks says *Scanning…* over the image, and the keep set is reported once the scan is done. The page lists finished scans above the one still running, and will not start a second one while one is running. With curator 0.6 (`/health` says `scan_control`), a *Stop* button sits beside the bar: the curator notices between images, the checks already in flight finish, and the partial scan is dropped rather than kept. *Purge all* under the scan list asks twice, then stops any running scan and deletes every cached scan from the curator; source images, labels and cohorts are not touched. A scan stopped or purged from another tab disappears from this one on the next poll. Blur lifts as soon as the NudeNet exposed score is under `ARGUS_CULL_BLUR_EXPOSED_SCORE` (default 0.25) and the ages are in, and comes back if policy marks the image unsafe. While face detection is still running, a frame with an exposed reading of 0.2 or more waits for its age; under 0.2 the under-18 rule cannot apply, so it does not. *Unblur NSFW* follows the same rule, so it never shows a frame whose under-18 status is still unknown. Set `ARGUS_CULL_POLICY_BLUR=0` to leave it off. With curator 0.11's EraX fill-in (`/detectors` says `erax`), a frame NudeNet scored nothing exposed takes EraX's hits mapped onto NudeNet's labels, and the NudeNet fold in the detail view says so. When NudeNet's check failed and EraX alone scored the frame, it stays blurred at any score until *Unblur NSFW*, because EraX has no buttocks class; curator's NudeNet filters likewise count it as unchecked. The grid can be sorted by that score, by the policy verdict, or by the youngest MiVOLO age, and the arrow reverses the order. An age range next to the sort hides other frames from the gallery without changing which files the scan keeps. Previous and Next in the detail view walk that order. Export uses the same bar. Changing the folder clears that scan from the page. Cached scans stay in the list, so a finished one can be opened again. Optional detectors are requested only when `GET /detectors` says they are loaded, so a missing ONNX file disables that filter group instead of failing the scan. The group names the convert command: `mivolo-convert`, `places365-convert`, or `garments-convert`.

Changing a filter calls `POST /scan/{id}/select`. Counts and `keep_reason` update without another scan. Rejected images stay on the grid.

A scan is set up in a form: *New scan* in the sidebar opens it with the folder browser, the SingGuard policy and variants, and the checks below, and nothing is written to the page until *Scan* is pressed, so browsing folders there leaves the scan on screen alone. The form's choices go into the URL as the scan starts (`folder`, `policy`, `variants`, `garments=on`, `set=1`), so a shared link opens the form filled the same way. The sidebar's *Scans* table lists every scan the curator holds, newest first, with the one running on top: a row opens its scan, and *Again* reads that scan's recorded config (`faces_config`, `garments_config`, `guard_config`) back into the form, so a second run of the same set differs only in what is changed before pressing *Scan*. *Run stats* in the header downloads a JSON file for the scan on screen: what it ran, pass and fail counts with the reject reasons, the keep set under the current filters with the reasons frames were left out, the ages read (frames with a face age, with the set's age, with none; mean, median and range of the MiVOLO readings; frames under 18 and frames the under-18 rule holds), NudeNet bands, each policy's flag rate, agreement and precision and recall against the labels, and the trigger tags: per setting, wardrobe or prop tag from `cohorts.json`, how often each policy flagged tagged frames against the rest of the scan, overall and within each NudeNet band. One file per run, so two runs of a folder under different parameters sit side by side.

Fashionpedia is off unless asked for: it is the slowest local check and nothing else waits on it. The *Checks* section of the scan form turns it on for that scan (`garments=on` in the URL); the wardrobe filters stay empty for a scan that ran without it.

A frame with no detected face has no MiVOLO age, and the tile's age cell says *no face* rather than *–* once face detection has reported. The *Faces* control beside the age range narrows the grid to those frames, or to the frames with a face, since the frames with the least to go on for the under-18 check are often the most explicit ones.

For a folder that is one set of one person, *Set: one person* under the form's *Checks* (`set=1` in the URL; curator 0.7, `/health` says `set_age`) asks the curator to give those frames the set's age: the median MiVOLO age of the scan's dominant identity, when that identity holds at least 90% of the faces. The tile shows it as *≈20y set* and the detail view says what it was read from; the sidebar says what the scan did with it, including why it gave nothing in a mixed folder. The set age counts where a wrong age is the costlier mistake: a set age under 18 with exposure holds the blur and marks the frame for delete, the same as a measured face. It never lifts a hold, since a frame with no face had no age before.

*Read bodies too (under evaluation)*, under the same *Checks* (`bodies=1`; curator 0.10, `/detectors` says `bodies`), asks for `faces.mivolo_body`: MiVOLO reads each person's body as well as the face, and a person the face detector missed gets an age from the body alone. The tile shows it as *15y body*, and the detail view lists it under *No visible face*. Cull counts a body-only age like a face's in the under-18 hold, *Select under-18* and the age sort, so it can only add holds. The curator goes further and pairs each age with the exposure on the same person's box; cull has no boxes, so a young age anywhere in an exposed frame holds it. It also outranks the set age, since the frame has a reading of its own. When the person check fails, the detail view says *Person detector failed; faces only* or *Body-only ages failed*, so an empty list is not read as "nobody without a face". In crowded frames most bodies are too covered to read, which is expected.

### SingGuard policies

When `GET /detectors` lists `singguard_policies` (curator 0.5 and later), the scan form offers the official policy for the next scan (`adult` by default) and the variants to run beside it for comparison. With curator 0.8 (`/health` says `guard_policy_text`), *Wording* under the picker and in the *Policies* panel is the text `GET /guard/policies` serves for that name: built-in, the operator's policy file, or SingGuard's own rules when `default` sends none. An unreadable file is listed with the env var, not the path. Curator 0.8.1's adult policies say what passes only under Safe; scans made before that were judged under the old wording. Each variant is another SingGuard pass per image. The official verdict drives the keep set, but a variant that flags where the official policy passes blurs the frame, puts an orange core in the tile's shield, and opens in the detail view, and the unsafe and rule filters send `guard_policies` so "Show left out" and export drop the same images. Each tile carries the file name, the quality score, the NudeNet exposed score, the apparent age, the keep reason, and a shield coloured by the verdict the shield follows: grey before a verdict, green passed, red flagged. An orange core in a green or red shield means another policy disagreed with that verdict. *Shield* next to *Faces* hides tiles whose shield does not match, with the same three queries: *Unsafe* is a red shield, *Split* an orange core, *Safe* a green shield; *All* keeps frames with no verdict. The control is hidden until a scan has a verdict, so a guard-off or still-running pass does not offer an empty Unsafe/Safe/Split. *Policy* next to *Select all* picks the current selection by that colour without hiding the rest: *Unsafe* is a red shield (the official policy, or the override, flagged; a passing variant does not clear it), *Split* is an orange core (the policies disagreed, including official-safe with a flagging variant), *Safe* is a green shield. Keep counts and the *Policies* panel follow the filtered gallery. *Select under-18* is separate: it selects the frames MiVOLO or the set age puts under 18 with an exposed reading of at least 0.2, which are the only ones *Delete selected* will remove. The detail view opens with those numbers in one strip, then the appearance table, then the quality, NudeNet, Places365 and Fashionpedia details folded, each under a one-line summary (the score and the reject reason or sharpness; the exposed score and the exposed classes that scored; the top scene and the environment; the top garments), then a table of every policy's verdict with the reasoning folded under it. The age on a tile and in the strip is always the youngest face or body-only person in the frame, the one the under-18 rule reads, so a younger second face is never hidden behind an older primary one; the tooltip and the appearance table name the primary face's age when it reads older.

The detail view also takes a label, in a section that starts folded until something is set: what a correct verdict is, using argus-curator's `guard_eval` values (`hard`, `ambiguous`, `adult`, `other`, `safe`), a *proxy* flag for a verified 18+ image standing in for a hard case, a per-image choice of which policy the shield follows, and a note. Labels are keyed by folder and path, so they survive a rescan under other policies, and are written as JSON under `CULL_LABELS_PATH` (default `./labels`). The *Policies* button shows each policy's flag rate, how often it disagrees with the official one, and its precision and recall against the labels, and downloads the labels as JSONL in the shape `scripts/guard_eval.py` reads.

### Setting and wardrobe cohorts

To compare how a setting or an outfit moves the flag rate for the same performer, `cohorts.json` at the repo root (mounted at `CULL_COHORTS_PATH`, read on every page load) names tags and the rules that apply them: `scenes` are Places365 categories as the curator records them, matched at or above `scene_min_conf`; `captions` are whole-word phrases matched against argus-lens sidecars next to the image (`<image>.txt`, and the keywords and description in `<image>.xmp`), which the web container reads from `CURATOR_SOURCE_PATH` mounted read-only. The shipped list is the narrow set most likely to read as an adult cosplaying a minor: classroom, kindergarten, schoolhouse, child's room, playroom, nursery, playground, library, gymnasium, locker room, and dorm room from Places365; school uniform, braces, lollipop, and backpack from captions. Fashionpedia garments are not used, as they have no uniform class. Each tag can be confirmed or removed per image in the detail view, in a section that starts folded unless a tag applies, where a by-hand list replaces the automatic one and *Automatic* hands it back. The grid narrows to one tag with the *Cohort* select, the tags are read in the detail view rather than on the tiles, and the *Policies* panel reads each policy's flag rate on tagged images against the rest of the view, overall and within NudeNet score bands, since an outfit changes the exposed score as well. The labels JSONL carries the tags per row. A broken `cohorts.json` or an unmounted source folder is reported in that panel.

Download paths writes two files in the browser and does not touch the export root: kept `rel_path`s, one per line, and a JSONL of `{rel_path, abs_path, keep_reason}` for every image. Export is separate. It copies, symlinks, or moves through `POST /export/stream`, then offers the manifest's `exported_abs_path` list. *Write XMP sidecars* on that dialog (`write_xmp`) writes face regions, the names from People, and the NudeNet content rating beside each exported file, merged onto the source's sidecar; ages are never written, and the source sidecar is not changed. The result names `xmp_written`. The rating facet, cluster names and XMP checkbox need curator 0.9.0. An older curator ignores the new fields.

People lists the clusters the scan already computed. A name field on each cluster is kept in the URL (`name=face_1:Ada`) and sent as `face_names` at export; two clusters can share a name. The cached scan is not changed. The shared URL holds the scan id and the filter.

NudeNet and SingGuard stay hidden until `/detectors` reports them. A threshold or a rule list is sent on the select and export bodies the server already accepts. The NudeNet group also has a content-rating facet (`safe` / `suggestive` / `explicit`, counts from the scan, `content_ratings` on `/select`): explicit is an exposed class at 0.2 or above, suggestive is a covered intimate class without that, safe is neither. An image NudeNet did not check is dropped once a rating is selected (`nsfw-unchecked`). Flagged frames stay blurred until you show the image. This page does not invent a score. The SingGuard policy a scan is judged under is picked in the scan form (below) and kept in the URL as `policy=` and `variants=`. Under `adult`, consensual adult nudity passes SingGuard while apparent minors, non-consent and sexual violence are still rule A, and the rule list names it that way. The policy does not change NudeNet scores, the blur line, or the rule that a MiVOLO age under 18 with exposure is never kept.

## Fixture

`fixture/` is a handful of drawn shapes: faces, scenes, garments, one identical pair, and one blurred frame. It is labeled as a fixture. CI installs `argus-curator` with no GPU extras and scans it.
